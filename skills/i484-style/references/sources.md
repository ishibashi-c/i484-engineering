# Sources and maintenance

i484-style consolidates the user-approved direction of three existing specialists into one entry with conditional domains. The source baselines, research ledgers, licenses, and attributions remain in each domain's sources.md. Original repository names there identify provenance, not runtime dependencies or current evaluation evidence.

## Model-aware design research

Official sources checked on 2026-10-02:

- [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna): target for scoped, efficient work; image creation remains a tool capability.
- [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra), published 2026-09-11: minimal entry, conditional supporting material, and explicit caution about different instruction needs for Luna and Sol.
- [Build skills](https://learn.chatgpt.com/docs/build-skills): concise activation descriptions and progressive disclosure. The initial catalog budget is not a full SKILL.md size limit.
- [Using GPT-6](https://developers.openai.com/api/docs/guides/latest-model): state instructions once; preserve style guidance that encodes requirements; validate removals on the actual workload.
- [Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills): positive and negative activation cases, actual traces, and lightweight deterministic grading.

These sources support the structure, not a claim that this skill has measured higher quality or lower cost on Luna. Keep the user preference and artifact contracts until representative runtime evidence justifies further removal.
