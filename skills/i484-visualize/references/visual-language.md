# 視覚言語

対象に既存のデザインシステムまたは合意済みの方向がないときに読む。特定のテーマを一律に当てるのではなく、主題固有の関係を現代的で精密な視覚資料として伝える。

## 方向を決める

読者、用途、主題、資料の寿命から、視覚的な性格を短く定める。色や書体を選ぶ前に、何を最初に理解し、何を比較し、どこで判断する資料なのかを構成へ反映する。

既存の方向がない技術資料では、次を基準状態にする。

- 背景は白またはニュートラルな無彩色に近いsurfaceとし、日本語本文と見出しには読みやすいsystem sans-serifを使う。
- コード、パス、識別子、数値など役割が明確な箇所だけ等幅書体を使う。
- hierarchyは文字サイズ、weight、余白、整列、proximity、細い構造線で作り、囲みとshadowは意味上の境界または浮遊状態を示す場合に限る。
- 色は軸、分類、状態、関係に安定して割り当て、大きな面積には低彩度、重要な線やmarkには必要なcontrastを使う。色だけに意味を担わせない。
- 図とデータを主役にし、UI chrome、凡例、操作部品、要約パネルは読解または探索に必要なものだけ置く。値と関係は可能なら直接labelする。

ベージュと明朝体、暗いコンソール、手描き風、強いgradientなどは、主題、ブランド、ユーザー指定に根拠がある場合の選択肢であり、洗練を演出する既定値にはしない。

## 構成の判断

表面表現より先に、資料の主要なcompositionを一つ定める。

- **連続文書:** 説明の順序と読書のリズムが中心。
- **構造図中心:** 一つの主要canvasと短い補足が中心。
- **比較:** 同じ比較軸を共有する表、並列図、small multiplesが中心。
- **作業手引き:** 順序、判断点、失敗時の戻り先が中心。
- **探索:** 入力または選択によって一つの主要visualが更新される。

containerを先に並べず、情報の関係からcompositionを選ぶ。同じ形を反復するのは対象が本当にpeerであり、読者が比較する場合に限る。無関係な題材へ内容だけ差し替えて成立する構成は、主題固有の関係へ組み直す。

## 図解の現代性

モダンな技術図は、装飾量ではなく、明確なgeometry、直接label、安定したsemantic color、低干渉なchrome、十分な余白、狭幅での読み替えによって作る。

- 描画前に、概念を実体、境界、常時適用される方針、条件付き能力、管理情報へ分類する。異なる役割を同じ矩形nodeの文法へ押し込まず、方針はframeやrail、能力はlaneやaxis、管理情報は主経路の外側など、関係に合う表現を選ぶ。
- 一つの主要経路または主要関係を最初に読めるようにする。
- node、edge、group、stateの見た目を意味上のroleへ対応させる。
- 関係線と境界は細くニュートラルにし、強調は検証済みの重要箇所へ限定する。
- 図全体を装飾的なcardやshadowで包まず、document flowの中へ直接置く。
- 自動配置を使っても、semantic label、reading order、衝突、空白の偏りを人が確認する。

## 既存方向と参考資料

対象Projectに正本のデザインシステムがあればReuseを優先する。参考資料からは、構成、文字のrole、surface、挙動の関係をAdaptし、固有のartworkや見た目を複製しない。適合する方向がない場合だけCreateし、その選択を成果物内または報告で説明できる状態にする。

`i484-product-design`から適応したのは、archetypeを先に選ぶこと、spacing・alignment・scaleをcontainerより先に使うこと、typographyとcolorをroleで扱うこと、汎用テンプレートを主題固有のcompositionへ変えること、Reuse／Adapt／Createの判断である。プロダクトUI固有のcomponent規則やV-routeは複製しない。
