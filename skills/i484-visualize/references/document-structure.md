# 文書の構成

内容に意図的なページ構成が必要な場合だけ、この参照文書を使う。

## 構成を選ぶ

- **記事**: 一つの概念または結論を、背景、例、限界で支える。
- **用語集主導の解説**: 主な議論の前に複数の用語または略語を理解する必要がある。
- **比較**: 選択肢が安定した比較軸を共有する。セマンティックな表と短い推奨を使う。
- **工程**: 単純な順序には番号付きの節を使う。分岐、フィードバック、並列作業がある場合はインラインSVGの図が有効なことがある。
- **時系列**: 出来事または版が時間順に並び、見える軸または日付グループを必要とする。
- **階層型解説**: 最初に要約を置き、次に仕組み、例、注意点、`details`ブロック内の任意の詳細を続ける。

すべての文書をこれらの節すべてへ無理に当てはめない。各節には一つの役割を持たせる。

## 記事の標準順序

1. タイトルとリード: 読者が理解または判断すべきこと。
2. 大きな節が複数ある場合は短い目次ナビゲーション。
3. 用語が本題への実質的な障壁になる場合だけ用語集。
4. 背景: なぜ主題が重要か、何を範囲に含めるか。
5. 主な説明: 仕組み、理由付け、または根拠。
6. 具体例、比較、または視覚モデル。
7. 限界、前提、未解決の問い、関連トピック。
8. 外部資料に依存する場合の資料と注記。

## 用語集のルール

用語が読者の理解の実質的な障壁になる場合だけ用語集を含める。読者が専門領域を知っているとは限らないこと、用語が繰り返し登場すること、用語の混同で解釈が変わること、後で参照・引き継ぎをすることだけでは、用語集を追加する理由にしない。必要な場合は項目数をおおむね3〜8件とする。

各項目には用語、平易な定義、必要に応じて「なぜ重要か」の一文を含める。用語は最初に意味を持って使う箇所でも定義する。用語集は地図であり、本文の明確さの代わりではない。

次のようなセマンティックなマークアップを使う。

```html
<aside aria-labelledby="glossary-title">
  <h2 id="glossary-title">用語</h2>
  <dl>
    <dt id="term-example">用語</dt>
    <dd>読者が本文を理解するために必要な短い定義。</dd>
  </dl>
</aside>
```

## 視覚表現の選択

- 関連するブロックと層にはCSSレイアウトを使う。
- ポータブルであり続ける必要がある小さな自作図にはインラインSVGを使う。
- すべての行が同じ比較軸を共有する場合は表を使う。
- 本題ではなく任意の深掘りに`details`を使う。
- ビジュアルが何を示すかをキャプションと近くの本文で説明する。説明のないラベルだけを図に担わせない。

## スタイルの基準

CSSはHTMLファイル内に置く。少数のカスタムプロパティ、読みやすい本文幅、レスポンシブな1カラムへのフォールバック、`:focus-visible`状態、`@media print`を使う。依存の重いコンポーネントライブラリ、外部フォント、CDNスクリプト、理解を改善しない装飾要素は避ける。

## 内容主導の編集設計

- 主題と読者に期待する行動から、記事、技術解説、比較資料、作業手引きなどの編集形式を一つ定める。社内向け解説を製品のランディングページとして扱わない。
- 本文の流れと文字組みを基礎にし、囲みは比較、状態、補足、まとまりなど意味上の境界がある場合に使う。すべての節を同じカードへ入れず、重要度に応じて余白、見出し、罫線、配置のリズムを変える。
- 色、形、装飾は階層、分類、状態、関係のいずれかを伝える場合に使う。ピル型ラベルは状態、フィルター、短いメタデータに限定し、飾りの見出しには使わない。
- 文書の主言語で自然な見出しとラベルを書く。英語は固有名詞、コード識別子、確立した専門語など、保持する意味がある箇所に限る。
- タイトルの大きさと冒頭の密度は文書の目的に比例させる。主張を一文で示せる場合でも、宣伝文句のような大見出しや内容を言い換えただけの副題を足さない。
- 無関係な題材へタイトルと本文だけを差し替えても同じ構成が成立するなら、構成が汎用テンプレートに寄りすぎている。主題固有の関係、比較軸、順序、判断点のいずれかを構成へ反映する。

## 完全HTMLの契約

成果物は、保存した単体ファイルをそのまま開ける完全なHTML文書にする。

- `<!doctype html>`を置き、`<html lang="...">`の値は文書の主言語に合わせる。
- `<head>`の先頭1024 byte以内に`<meta charset="utf-8">`を置き、意味のある`<title>`とviewportメタデータを含める。
- CSSは埋め込み、表示に必須な外部CSS、font、script、image、iframeなどへ依存しない。静的確認では外部URLを指す表示依存（例: `link`／`script`／`img`／`iframe`の参照やCSSの`@import`／`url()`）を確認し、内容上必要な参考資料への`a href`は表示依存と区別する。
- 意味のある別言語のまとまりには部分`lang`を、右から左へ読む内容には必要に応じて`dir`を付ける。
