# Native model selection

Read this file immediately before each native subagent or reviewer dispatch. The caller records `class` as `bounded` or `critical` and owns task classification; a persona name alone does not make a task bounded.

A delegated job is **bounded** only when its scope, inputs, and authoritative acceptance criteria are fixed before launch. Routine extraction, comparison, or a small change with a settled cause and acceptance check can qualify. Critical correctness, security, adversarial analysis, architecture, full research interpretation, and final synthesis inherit the parent model. Do not create an agent for work too small to justify its context and launch cost.

Resolve `native_subagent_models` from ordinary configuration layers per key: checkout-local `config.local.yaml`, then team `config.yaml`, then the skill default. Active user and Global instructions take precedence. Each host entry has a required nonempty `model` string and optional `effort` string supported by that host. A present map replaces the entire `native_subagent_models` value; an empty map disables the configured override. The host key names its native dispatch host. Use a configured model only when the host supports it and it is known to be at or below the parent's capability; the parent's capability is the ceiling. Unknown model, hierarchy, host support, or override surface means inherit and record why. Do not replace an explicit execution engine or explicit review target.

When a bounded job has a valid configured override, pass the selected model and effort as actual dispatch arguments. Prompt wording is not a model override. Start a fresh worker context when required by the dispatch mechanism. Record the selection with these fields: `task`, `class`, `reason`, `requested_model`, `requested_effort`, `launch`, `outcome`, `validation`, `served_model`, `served_model_evidence`, and `fallback_reason`. Use `inherit` for parent work rather than inventing a worker ID. Leave `served_model` unknown and its evidence null unless the host proves what served the run.

Attempt one bounded-model run for the job. Allow one correction for a rejected pre-launch argument. Treat capacity limits as a queued launch and wait for capacity. If dispatch remains unavailable or acceptance fails, stop the old writer before parent takeover, then reuse its artifacts and diff. The parent continues inline or inherits its own model; do not retry without bound or switch to an unapproved provider/API/shell route. Unknown served model alone does not justify rerunning. Do not claim cost savings without measured cost evidence.
