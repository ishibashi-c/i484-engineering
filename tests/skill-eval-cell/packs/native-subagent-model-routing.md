# Native subagent model routing — targeted behavioral cases

This pack covers the native dispatch decision in ce-code-review, ce-doc-review,
ce-simplify-code, ce-plan, ce-explain, and ce-work. Extract/inject current on-disk
skills and their local native-model-policy references into fresh contexts. Keep
fixture writes outside the authoring repository. Run the reachable Codex and
Claude hosts; record an unavailable host explicitly rather than imply coverage.
Static parity/config tests are separate from these behavioral cases.

## Live cases

1. Ask ce-explain to delegate a fixed source-field inventory. Supply two exact
   input files, native host model configuration, and an independent field/line
   checker. Inspect actual launch arguments and receipts, not a prompt naming a
   model. Parent accepts only fields that actually exist with matching pointers.
2. Ask ce-work to fix one known broken local link in a temporary README. Keep
   destination content immutable. Accept exactly one replacement and all final
   links resolving; preserve the before/after evidence and actual model/effort.

## Inert negative controls

Feed a rejected native launch and a failed acceptance result as fixture data.
The owner permits at most one pre-launch argument correction; otherwise it takes
existing artifacts/diff over on the parent, after the old writer has stopped.
A capacity rejection queues the same job until capacity returns. Never induce
fatal signals, paid fallback, or extra model runs just to obtain these outcomes.
Record decision-only controls separately from any live failure exercised.

## Boundary cases

- Correctness/security/adversarial review, architecture, research interpretation,
  and final synthesis inherit the parent. The critical role roster survives.
- A Luna parent stays Luna; the supporting tier cannot cause an upgrade.
- Unknown model ordering or override support without a higher-priority assignment
  inherits with the reason. Explicit engine/review assignments remain intact.
- A receipt exposing only a task handle leaves served identity unknown. Successful
  output may be accepted; missing identity alone never causes another run.

## Evidence and grading

Preserve source hashes, exact launch model/effort/context arguments, selection
reason, terminal outcome, independent acceptance, and takeover artifacts when
applicable. Use the policy's receipt fields. A launch acknowledgement is not a
completed result. No cost percentage can be inferred from model selection.

The 2026-10-02 Codex native run requested gpt-6-luna/medium for two live cases;
source extraction and one-link repair passed independent acceptance. Serving
identity was not exposed. The six boundary/failure controls were decision-only
fixtures, not live rejection/capacity/takeover events. Claude was unavailable on
this PC. No live pre-change A/B arm or savings measurement was performed.
